# 通用视频创作项目管理工作台（video-creation-workbench）

带货 / 短剧 / 科普类短视频的**全流程创作项目管理台**：覆盖从选题、脚本、分镜、提示词，到生图、配音、图生视频、合成交付的端到端节点管理。配套 PC 网页原型 + 本地 Node 数据服务，支持多项目并存、流程状态机、节点输入输出区与三档权限。

> 结论先行：本仓库是**工作台源码与实例文档库**，不含任何生成素材（图片/音频/视频）。所有产出文件保留在本地磁盘，不进入 Git（见 [Git 仓库策略](#git-仓库策略)）。

## 功能特性

- **多项目管理**：每个项目独立目录、独立元数据与变更日志
- **流程状态机**：N00 初始化 → N02 脚本/分镜/提示词 → N06 生图 → N08 配音 → N09 图生视频 → N10 合成 → N11 质检 → N12 交付
- **节点输入输出区**：每个节点明确输入/输出/提示词/素材/产物/命名规约
- **本地 Node 数据服务**：零依赖 `http`，只监听 `127.0.0.1`，只读扫描项目目录，服务端强制三档权限 + 审计日志
- **模型协作层**：优先使用本机 WorkBuddy 模型能力，支持用户自定义 LLM / 生图 / 视频模型；企业认证前以「任务包桥接」半自动模式运行
- **三档权限矩阵**：① 全部（含删除）② 仅读写禁删除 ③ 每次新增/修改/删除需显式确认

## 技术栈

- 前端：原生 HTML / CSS / JavaScript（无构建步骤，单页多视图）
- 后端：Node.js 内置 `http` 模块（零三方依赖）
- 媒体生成：WorkBuddy 生图 / 图生视频 / 配音能力，及可插拔的外部模型（MiniMax 等，凭据走环境变量）

## 快速开始

### 启动本地数据服务 + PC 原型

```bash
cd prototype/pc-v1
node server.js
# 浏览器打开 http://127.0.0.1:8791/
```

> 或双击 `start-server.bat`（Windows，自动定位本机 Node 可执行文件）。服务只监听本机回环地址，不对外暴露。

### 运行节点脚本

`scripts/` 下为各节点的可执行脚本（以 DJ04 为例）：

```bash
node scripts/tts_final_v2_DJ04.js      # N08 配音（Edge TTS，本地免费）
node scripts/compose_n10_v2_DJ04.js    # N10 合成成片（ffmpeg）
node scripts/n11_qc_DJ04.js            # N11 质检（ffmpeg 解码校验）
node scripts/n12_archive_DJ04.js       # N12 交付清单生成
```

> 视频合成依赖 `ffmpeg`，需本机预装并加入 PATH。

## Git 仓库策略

**代码仓库仅保留源代码相关文件和实例相关文件；生成素材与产出文件一律不入仓。**

- **入库**：`prototype/`、`scripts/` 源码；各 `projects/*` 的 Markdown 脚本/提示词、JSON 清单（`assets.index` / `voice-manifest` / `qc-report` / `compose-params` / `delivery-manifest` 等过程文档）；根目录需求/复盘文档。
- **不入库（保留在本地磁盘）**：
  - 二进制媒体：`*.png` `*.jpg` `*.mp4` `*.mov` `*.webm` `*.mp3` `*.wav` `*.m4a` `*.aac` `*.ogg` 等（生图、配音、视频片段、成片、质检帧）
  - 原始输入样本：`短剧实测/`（约 209MB，建议 Git LFS 或外链）
  - 本地运行数据：`*.log`、`data/ops.log`、`data/localStorage-backup-*.json`、浏览器冒烟 profile
  - 代理内部数据：`.workbuddy/`
- 排除规则按**文件扩展名**实现（而非整目录），以保留 `04_output/qc/` 等目录下的文本过程文档。
- 提交产出文件后如需「退出 Git 跟踪但保留本地文件」：

```bash
git rm --cached --pathspec-from-file=<清单> --pathspec-file-nul -q
git commit -m "chore: 将生成素材移出版本库"
```

## 数据安全红线

1. **线上真实业务数据：只读，零写入、零接入。** 所有写操作先说明影响范围并取得当轮明确确认。
2. **凭据只查环境变量**（`process.env`），不落地文件、不回显 secret。
3. **计费能力（生图 / 图生视频 / 第三方 TTS 等）每次确认**，项目级「默认不再提示」仍需审计留痕。
4. **不可逆操作**（删字段、删记录、改类型）风险等级更高，同样走「先说明 → 等确认」并强调不可恢复。
5. 服务端对三档权限矩阵**强制校验**，前端绕过无效。
